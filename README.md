# 食品召回公告采集质量核查

食品仓库质控员使用的小型工具：输入生产商召回公告**列表页 URL**，自动沿**同站分页**读取列表，
逐条打开详情页核对**公告编号**、**GTIN（含校验位）** 与 **六位批号**，并只在全部核对通过时
发布完整清单。任何异常都会列出**具体地址与原因**，绝不发布部分公告或伪造"无召回"。

## 核心规则

| 情况 | 行为 |
| --- | --- |
| 列表结构无法识别（改版后缺少公告编号列等） | **报异常**，列出列表页地址与原因，不发布 |
| 列表为空且页面**明确标示为空**（`暂无召回公告` 等） | 发布空清单（0 条） |
| 列表为空但**未明确标示** | **报异常**，不发布 |
| 详情页缺少公告编号 / GTIN / 六位批号 | **报异常**，列出该详情页地址与缺失字段 |
| GTIN 校验位错误、批号不是六位数字 | **报异常** |
| 列表公告编号与详情编号不一致 | **报异常** |
| 同一公告编号在**跨页/多详情页**中 GTIN 或批号冲突 | **报异常**，列出全部冲突地址与两边的值 |
| 详情链接指向站外、分页链接指向站外 | **报异常**，拒绝抓取 |
| 成功采集 | 保存该 URL 的**完整清单 + 采集时间**，原子写入磁盘 |
| 采集失败 | 保留上次成功清单，标记为**旧数据**；重启后仍可查看 |

补充约束：

* 分页只跟随页面中**显式存在**的"下一页/页码"同站链接，不会自行拼造 `?page=n`，
  避免改版后陈旧链接导致漏抓或多抓；分页循环、超过 300 页或超过 1000 条公告会中止。
* 空页与非空页混在一起、或先空后非空，均视为分页不完整，报异常。
* 页面体积、正文长度和解析 token 数都有上限，超限按异常处理。

## 快速启动（Docker Compose，推荐）

```bash
docker compose up --build
```

* 质检页：<http://localhost:8000>
* 本地示例站：<http://localhost:8080>

质检页顶部有"本地示例站"快捷按钮，可直接对示例站发起核查。浏览器访问示例站用
`http://localhost:8080`，而容器内服务抓取示例站使用 `http://example-site:8080`
（由 Compose 环境变量 `EXAMPLE_SITE_INTERNAL_URL` / `EXAMPLE_SITE_PUBLIC_URL` 配置）。

数据保存在 Compose 卷 `recall-data` 中；`docker compose down`（不加 `-v`）后重启，
已保存的清单与"旧数据"标记仍在。

## 无 Docker 的本地运行

```bash
./run_local.sh
# 质检页: http://127.0.0.1:8000   示例站: http://127.0.0.1:8080
```

仅依赖 Python 3.11+ 标准库，无需安装第三方包。

## 本地示例站场景

| 路径 | 场景 | 预期结果 |
| --- | --- | --- |
| `/recalls/list` | 正常两页表格列表（3 条） | 成功发布 3 条 |
| `/recalls/list-v2` | 页面改版：卡片式列表 + 另一种详情布局 | 成功发布 3 条（兼容改版） |
| `/recalls/list-broken` | 改版故障：列表丢失公告编号列 | 异常"列表结构无法识别" |
| `/recalls/empty` | 明确标示为空 | 发布空清单 |
| `/recalls/empty-broken` | 空白列表但未标示为空 | 异常"未明确标示为空" |
| `/recalls/conflict` | 同一公告编号跨页出现且详情内容冲突 | 异常并列出两边地址与数值 |
| `/recalls/missing` | 详情页缺少六位批号 | 异常"详情页缺少六位批号" |
| `/recalls/flippable` | 正常列表，可切换为改版故障 | 先成功，切换后再核查 → 失败并保留旧清单（旧数据） |

离线浏览器核查流程（验证"失败保留旧清单"）：

1. 打开 <http://localhost:8000>，点击「可切换列表」→ 成功发布 3 条。
2. 打开 <http://localhost:8080/>，点击「切换为改版故障」。
3. 回到质检页再次点击「可切换列表」→ 显示异常地址与原因，旧清单仍在并标注"旧数据"。
4. 打开「恢复正常」后重新核查 → 状态恢复为当前清单。

## 页面行为

* 输入框只接受 `http(s)` URL；主机部分与列表 URL 不同的链接一律拒绝。
* 成功：绿色横幅 + 公告表格（编号 / GTIN / 批号 / 详情页）+ 采集时间与已读取的列表页；
  空清单会明确显示"该列表明确标示为空，已发布空清单（0 条公告）"。
* 失败：红色横幅 + **异常地址及原因**表格；若有旧清单则额外显示"旧数据"清单。
* 首页列出所有已保存清单（含采集时间与旧数据标记），可点入只读详情页；清单也可导出为 JSON。

## 数据格式

每条清单一个文件，`<sha256(url)[:32]>.json`：

```json
{
  "version": 1,
  "list_url": "http://example.com/recalls/list",
  "collected_at": "2026-11-12T09:06:11Z",
  "notices": [
    {"number": "N-2026-001", "detail_url": "...", "gtin": "6901234567892",
     "batch": "000123", "collected_from": "http://example.com/recalls/list"}
  ]
}
```

失败只写 `<key>.status.json`（旧数据标记），成功发布时自动清除该标记。
清单文件先写临时文件再 `os.replace`，崩溃不会留下半份清单。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：HTML 容错解析、列表/详情识别、GTIN 校验位、批号长度、分页安全、站外链接、
明确的空 vs 未标空、跨页冲突、失败保留旧清单并跨重启标记旧数据、HTTP 页面渲染。

## 文件结构

```
app/
  htmltree.py    容错 HTML 树（标准库实现）
  collector.py   列表识别、同站分页、详情核对、跨页一致性
  validation.py  编号/GTIN/批号的规范化与校验
  storage.py     清单快照（原子写入、旧数据标记）
  service.py     一次核查的编排：发布或保留
  fetcher.py     受限 HTTP 抓取（大小/超时/站外重定向）
  server.py      标准库 Web UI
example_site/    本地示例站（含改版、空列表、跨页冲突、可切换场景）
tests/           单元与端到端测试
```
